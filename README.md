# 研途 · 黑客松赛道三作品原型

面向刚接触科研的学生：**先用一个搜索框找到论文，再由用户决定「轻度审查 / 深度审查」，AI 此刻才介入**。解决找资料繁琐、术语看不懂、多篇同质论文难以找共性、创新点与结论边界不易判断的问题。

> 当前为**零依赖、可离线演示**的 Web 原型。内置 12 篇拟真题录（非知网真实数据），用于完整走通交互；真实数据源与大模型均留有标准接口，替换后 UI 与分析层不用改。

---

## 核心价值：把论文检索变成科研入门工作流

**解决的需求**：科研新手常要在多个平台反复找资料，面对专业术语难以入门；读完单篇也难以比较同主题研究、识别创新点并判断结论边界。研途把这些分散步骤收在一个工作台里，让用户从“我想研究什么”走到“我读懂了什么、下一步学什么”。

**模型如何融入**：模型不替用户盲搜，也不在每次输入时自动生成答案。检索阶段使用结构化条件定位可复核的论文；用户选定论文后，再按需触发摘要理解、术语解释、翻译、多篇比较、五步证据核查或学习路径。AI 的输入范围、任务和触发时机都由用户掌控；信息不足时明确标出待核验，不把模型推测伪装成论文事实。

**带来的新能力与体验**：传统检索平台主要回答“有哪些论文”，聊天机器人主要回答“如何解释问题”。研途把两者连接起来：每个 AI 解释都锚定到用户选中的题录，结果可以回到来源复核；从单篇理解延伸到跨论文共性、创新线索、结论边界和下一步学习。用户不用在搜索、翻译、笔记和对比工具间来回搬运材料。

**新的软件形态与可扩展任务**：它不是一个套了聊天框的论文搜索页，而是“可验证检索 + 用户编排的 AI 研究工作台”。同一工作流可扩展到选题调研、课程阅读、文献综述准备、研究方法学习和组会汇报准备；底层数据源与模型可替换，任务能力可逐项增加。

**核心任务闭环**：输入主题与筛选条件 → 浏览并选择论文 → 选择轻度 / 深度审查或中译 / 对比 / 学习 → 查看带证据与待核验项的结果 → 导出笔记并继续学习。搜索与筛选是主路径，AI 能力是用户明确选择的后续动作，减少误搜、信息过载和无依据总结。


## 5. 架构与文件

```
检索层（不调用 AI）
  输入 → parseQuery(自然语言) → SearchProvider → 题录列表 → 结果卡片
                                      ↑ 可替换：demo / openalex / custom
分析层（用户点击后才启动）
  用户选择 → AIProvider.analyze(task, payload) → 审查报告 → 导出 Markdown
                     ↑ 可替换：demo / openai 兼容接口 / custom
```

| 文件 | 作用 |

| `assets/app.js` | 状态管理、卡片渲染、对比篮、审查抽屉、导出与设置 |
| `tests/smoke.js` | 离线自检：检索式、筛选、报告、五步核查完整性 |
| `tests/dom-smoke.js` | UI 初始化与首屏渲染自检 |
| `tests/network-guards.js` | 请求取消、15 秒超时与 AI 输出边界回归测试 |

| `docs/sample-cnki-export.csv` | 模拟知网导出文件，用于演练「导入题录」流程 |

**为什么坚持两层解耦**：检索结果可复核、可排序、可量化（下载量/被引量这类指标大模型编不出来）；AI 只在用户选定对象后基于题录分析，既省 token，也避免「AI 自己搜出一篇不存在的论文」。这是本作品相比「直接接一个聊天机器人」的核心差异点。

## 6. 接真实数据：学校 WebVPN / 知网（重要）

### 6.1 技术现实

对 `https://webvpn.hdu.edu.cn/_webvpn_/https://www.cnki.net` 的探测结果：未登录时 **302 跳回** `https://webvpn.hdu.edu.cn?returnUrl=...` 的统一身份认证页。也就是说 WebVPN 是**浏览器会话级代理**——会话 Cookie 只存在于你登录后自己的浏览器里，静态前端页面无法复用，AI 也不能代替你输入学校账号密码（更不要把凭据写进代码、配置或聊天里）。

知网没有面向个人的公开检索 API，网页爬取既有反爬限制也涉及服务条款与版权风险。所以作品采用「**你自己合法登录后导出题录 → 导入原型**」的路径，既真实可演示，也不碰凭据与全文。

### 6.2 路径 A：导出题录导入（已实现，现场最稳）

1. 在 **知网（学校 WebVPN）/ PubScholar / 万方** 任一平台检索并勾选文献（PubScholar 免费开放，知网需本人登录 WebVPN）；
2. 站内「导出 / 导出与分析」→ 选 **CSV / RefWorks / EndNote / BibTeX** 格式；
3. 研途顶部点 **「导入题录」** → 选来源平台 → 选文件或直接粘贴内容 → **「解析并导入」**；
4. 题录立即进入检索池，带「导入题录 · 指标待核」与来源平台标签，可用同一个搜索框检索、轻度/深度审查、多篇对比、引用、导出笔记。

- 支持：CSV / Excel 另存（知网「题名 / 下载量 / 被引」、万方「篇名 / 刊名 / 被引次数 / 主题词」等列名均可）、**BibTeX**（PubScholar / Zotero / 万方通用）、EndNote·RefWorks·NoteExpress 标签（TI/T1、AU/A1、PY/YR、SO/JF、AB、KW）、JSON 数组、以及直接复制的结果页文字（尽力解析）。示例文件：`docs/sample-cnki-export.csv`。
- 导入数据只存本机浏览器，优先使用 IndexedDB，旧浏览器回退到 localStorage，不上传；弹窗内可一键清空；刷新页面自动恢复。
- 导出文件通常没有下载量 / 被引量 / 层次，导入题录会保留在结果中并把缺失字段显示为「未知」，筛选不会把未知记录误判为满足条件；深度审查会把缺失字段统一标成「需人工核验」「证据不足」，**绝不编造实验设计、撤稿记录或结论**。

### 6.3 路径 B：自动检索（可选，需队员自己实现本机后端）

- 设置里选「自定义检索接口」，实现 `POST /api/search`：请求 `{ keywords, filters }`，返回 `{ items: [Paper], note }`；`API Base URL` 留空即同源。
- 骨架见 `backend/api-search.example.js`（`node backend/api-search.example.js` → 打开 `http://localhost:5174`）。它只检索 `backend/local-bibliography.json` 里你自己放好的题录，**不含任何知网请求、账号或 Cookie**。
- 若要接实时检索：会话凭据只放后端环境变量，仅转发你手动发起的单条检索、仅取题录元数据、低速、不批量抓取、不下载全文，并遵守学校图书馆与知网的使用条款。前端不接触 Cookie、不存密码。

### 6.4 其他数据源

- **公开学术库**（原型已内置）：设置里切到 `OpenAlex 实时检索`，无需密钥即可拿首屏 50 条真实题录；填写可选 OpenAlex API Key 后启用游标分页，最多加载 100 条，并保留 DOI、OA 状态、撤稿信号、来源链接与抓取时间。也可接 Crossref / Semantic Scholar / arXiv。中文学位论文覆盖有限，且没有「下载量」字段。
- **机构接口**：学校图书馆若提供正式 API，按同一 `Paper` 结构接入即可。

`Paper` 最小字段：`id, title, authors[], org, year, venue, level, lang, downloads, citations, field, keywords[], abstract, method{sample,control,stats,dataset}, conclusion, innovations[], limits[], terms[{t,d}], notes[5], score, minutes`。外部数据还会保留 `doi, sourceUrl, sourceProvider, retrievedAt, oa, oaUrl, retractionStatus, _missing`。

**大模型接入**：设置里选 `OpenAI 兼容 chat/completions`，填 Base URL / Key / 模型名（也可选自定义 `POST /api/review`）。提示词里硬性约束「只依据给定题录作答，信息不足必须写需人工核验，不得编造全文、撤稿记录、原始数据」。接口不可用时**自动回退离线引擎并明确提示**，现场演示不会中断。AI Key 与 OpenAlex Key 只保存在当前浏览器会话。

> 浏览器直连第三方 API 可能被 CORS 拦截，正式部署请在后端做代理。所有分析输入仅限用户已合法取得的题录与摘要，系统不自动下载或分发全文。

### 6.5 参考平台对照（答辩可用）

参考链接：`https://pubscholar.cn/explore`、`https://www.wanfangdata.com.cn/index.html/`

| 平台 | 定位与可及性 | 值得借鉴的能力 | 本作品的做法 |
|---|---|---|---|
| **PubScholar 公益学术平台**（中科院文献情报中心） | 公益免费开放，聚合论文 / 科学数据 / 图书 / 专利等；结果带原文链接（维普、期刊官网、DOAJ、作者共享）、`Open Access` 标记、「引用」「翻译」按钮；AI 检索、智能综述、AI 对话、文献精读由星火科研助手支持，AI 功能需登录，页面标注「内容由 AI 生成，仅供参考，请鉴别后使用」 | 结果卡片信息密度、AI 能力按入口拆分、对 AI 结果的谨慎提示 | 卡片加 OA / 原文渠道 / 卷期页 / 来源平台 / 引用；能力拆成轻度·深度·对比·中译·学习路径；把「仅供参考」升级为逐项「待人工核验」清单 |
| **万方数据知识服务平台** | 面向科研学习全流程，通常需机构账号；提供万方选题、科慧、关键词知识脉络、主题分析、万方检测、科研诚信学习 | 关键词知识脉络 / 主题分析、科研诚信视角 | 多篇对比新增「关键词知识脉络 · 主题演进」；五步核查中的引用核查对应诚信规范 |
| **知网 CNKI**（学校 WebVPN） | 会话级代理，需本人统一身份认证登录；无面向个人的公开检索 API | 中文学位论文覆盖与下载量 / 被引指标最全 | 用「导出题录 → 导入」接入，指标缺失自动降级，不代登录、不抓取 |

**差异化三句话（建议直接讲）**：

1. 它们把 AI 放在检索之前或检索之中（AI 检索 / 智能综述），我们坚持**先结构化检索、再由用户点选调用 AI** —— 下载量、被引量、机构这些指标来自题录而非模型生成，结果可复核。
2. 它们的 AI 提示「仅供参考，请鉴别」，我们把「鉴别」做成**五步核查 + 证据强度 + 具体待核验动作**，新手知道该去核什么、去哪儿核。
3. 不绑定单一平台：题录导入兼容知网 / PubScholar / 万方 / OpenAlex 的导出格式（CSV、RefWorks、BibTeX、JSON），学校有什么权限就用什么数据。

## 7. 严谨性设计（对应配图五步核查）

深度审查不是「夸论文」，而是按 **来源 → 方法 → 数据 → 引用 → 结论** 逐项给出证据强度（较充分 / 需补充核验 / 证据不足）和一条具体的待人工核验动作。系统明确声明：它不会自动访问全文、撤稿库或原始数据，凡信息不足处一律标注需人工核验，不替用户下结论。演示数据里特意放了一篇著录不全、结论外推过宽的「低质量论文」，用来展示核查能发现问题，而不只是生成漂亮摘要。

## 8. 已知限制 / 下一轮迭代

- 内置 12 篇为拟真题录，现场务必说明「数据可替换」；真实数据走 6.2 的导入或 6.3 的自建接口。**WebVPN 会话无法由前端或 AI 代登录**，这一步必须本人在浏览器完成。
- 导入题录常缺下载量 / 被引 / 实验设计，对应筛选不生效、审查自动降级，这是刻意设计而非缺陷。
- 离线审查引擎是结构化模板生成，不是大模型生成；接真实 LLM 后文笔更自然，但需要保留证据强度与待核验约束。
- 尚未做：用户登录与阅读历史、PDF 全文解析、引用关系图可视化、生成式综述草稿、PWA 离线缓存。
- **Web 还是 App**：3 天赛程建议先做 Web（响应式已做好，手机浏览器可直接演示），后续用 PWA / WebView 壳封装成 App，不建议同时开双端。
